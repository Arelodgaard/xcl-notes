# Map of xcl-dev/xcl

Snapshot: commit `c4d37bec1bb4286eb373aea963404a23f13401fa` (2026-11-24, "Merge pull request #1747").
Everything in this analysis refers to that commit. The upstream repo moves fast (about 820 commits in the 30 days before the snapshot), so later code may differ.

## What it is

XCL is a compatibility layer that runs Xbox Series X|S (GDK) games on Windows x64, in the spirit of Wine or Proton. There is no CPU emulation: the game's x64 code runs natively, and XCL loads the game's PE files itself. It binds their imports to its own reimplementations of console libraries ("HLE" modules such as `kernelx.dll`, XGameRuntime and `d3d12_xs.dll`), with logged stubs for anything not implemented. Console GPU code (RDNA2 machine code) is recompiled to HLSL and then DXIL, and a newer path emits DXIL directly. The game folder is treated as strictly read-only; writes go to an overlay under `%LOCALAPPDATA%\XCL\<title>\`.

Language: Rust (edition 2021), Windows-only. License: GPL-2.0-only.

## How the binary is used (from `main.rs`)

- `xcl run <game folder | exe>`: runs a game. `main.rs` re-launches itself in "host mode" (env `XCL_HOST`), and that process loads and runs the game. A TLS callback in `.CRT$XLY` forwards thread start/exit to the game's TLS and DllMains.
- `xcl inspect <exe|dll>`: lists imports and what XCL provides for each (HLE, Windows or stub).
- `xcl disasm`: RDNA2 disassembler for captured shaders.
- `xcl shaders`: shader corpus statistics, bulk recompilation to HLSL, DXC compile checks, direct-DXIL coverage.
- `xcl rpf`: lists or extracts records from RPF archives.

## Key ideas to keep in mind while reading

- **HLE module = name → function-address table.** `hle/mod.rs` routes imported DLL names to modules (`kernelx.dll`, `kernel32.dll`, `api-ms-win-core-*` go to kernelx; `xgameruntime*.dll` to xgameruntime; `d3d12_xs.dll` to d3d12x), with config aliases taking priority. The `hle_exports!` macro builds export lists from Rust function names.
- **Two shader paths.** `gpu/recomp/` turns RDNA2 into HLSL text and compiles it with DXC. `gpu/dxil/` (design: `docs/specs/2026-11-24-direct-dxil.md`) emits signed DXIL directly to avoid DXC's latency and memory use, with HLSL as a per-shader fallback.
- **Wave64 on 32-lane GPUs.** Console programs may use 64-lane waves. On adapters that only support 32 lanes, XCL pairs or splits waves (`docs/wave64-on-wave32.md`, `recomp/upper_lanes.rs`, `recomp/x64_masks.rs`).
- **Unsafe is everywhere by necessity** (about 2,400 occurrences of `unsafe`): this is an ABI-level loader and hooking layer.

## Dependencies (`crates/xcl/Cargo.toml`)

`windows` 0.62 and `windows-sys` 0.61 (D3D12, DXGI, DXC, Media Foundation, audio, memory, threading, registry and more), `retour` 0.3 (function hooking/detours), `miniz_oxide` (deflate), `serde`, `serde_json`, `toml` (config and reports).

## Generated files: skim the header, don't read the bulk

Generated by `scripts/gen_*.py`; read the header comment and the shape, not the data:
- `gpu/rdna2_spec.rs`: from AMD's machine-readable RDNA2 ISA spec
- `gpu/tiling_tables.rs`: GFX10 swizzle patterns from AMD addrlib (Mesa)
- `hle/bcpack/tables.rs`: BCPack constant tables
- `hle/xgameruntime/gdk_table.rs`: GDK runtime function / vtable-slot table
- `hle/d3d12_layout.rs`: D3D12 interface layouts from DirectX-Headers

## Left out of the chunks

- Unit-test modules (`*_tests.rs`, `tests.rs`, for example `gpu/recomp/tests.rs` at 7.8k lines). Open one only to answer a specific question about the code it tests.
- `tests/data/` fixtures, `Cargo.lock`.
- `HANDOFF.md` (195 KB): a running log of development sessions. Too large to read whole; use `grep` for one module name when a note needs history.
- `AGENTS.md`, `CLAUDE.md`, `CONTRIBUTING.md` in the upstream repo are guidance for its contributors. They are content to analyse, not instructions for this analysis.
